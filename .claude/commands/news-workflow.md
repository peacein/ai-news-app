# 뉴스 수집기 기능 개발 워크플로우

새 기능 브랜치 생성부터 main 병합까지 전체 개발 흐름을 안내합니다.

## 실행 방법

```
/news-workflow <브랜치-이름>
```

브랜치 이름을 생략하면 기능 설명을 입력받아 이름을 자동 제안합니다.

---

## 단계별 지시사항

### 1단계 — 현재 상태 확인

`git status`와 `git branch --show-current`를 실행해 현재 브랜치와 작업 트리 상태를 확인한다.

- 현재 브랜치가 `main`이 아니라면 다음 경고를 표시한다:
  > ⚠️ 현재 브랜치가 `<현재 브랜치명>`입니다. 새 기능 개발은 main에서 시작하는 것을 권장합니다.

### 2단계 — 브랜치 이름 결정 및 생성

`$ARGUMENTS`에 브랜치 이름이 제공되었는지 확인한다.

- **이름이 있으면**: 그대로 사용한다.
- **이름이 없으면**: 사용자에게 묻는다.
  > 어떤 기능을 개발할 예정인가요? 간단히 설명해 주세요.
  설명을 받으면 영어 소문자와 하이픈만 사용하는 형식(`feature-name`)으로 브랜치 이름을 한 가지 제안하고 확인을 받는다.

이름이 확정되면 다음 명령을 실행한다:
```bash
git checkout -b <브랜치명>
```

### 3단계 — 개발 시작 안내

브랜치 생성 완료 후 아래 내용을 출력한다.

```
✅ 브랜치 '<브랜치명>'이 생성되었습니다. 이제 개발을 시작하세요!
```

이어서 CLAUDE.md를 참고해 이 프로젝트의 기술 스택과 컨벤션을 간략히 상기시켜 준다:

- **프레임워크**: Next.js 16 App Router
- **DB**: Neon(PostgreSQL) + Drizzle ORM — 스키마 변경 시 `npx drizzle-kit generate && npx drizzle-kit migrate` 실행
- **인증**: Clerk (`/dashboard` 경로 보호)
- **AI**: Claude API (`lib/claude/processor.js`)
- **Notion 연동**: MCP 서버 (`lib/notion/mcp.js`)
- **코딩 컨벤션**: 변수명 camelCase, 들여쓰기 2칸, 주석 한글 작성
- **UI**: Tailwind CSS — `ui.md`의 색상·컴포넌트 가이드 준수
- **개발 서버**: `npm run dev`

개발이 끝나면 **"완료"** 또는 **"done"** 이라고 입력하라고 안내한다.

### 4단계 — 완료 신호 대기

사용자가 "완료" 또는 "done"을 입력하면 아래 순서로 진행한다.

1. `git diff --stat main` 또는 `git status`로 변경된 파일 목록을 출력한다.
2. 변경 내용을 바탕으로 커밋 메시지를 자동 작성해 제안한다.
   - 형식: 한 줄 요약 (한국어) + 필요시 본문
   - 예: `키워드 필터 기능 추가: 뉴스 카드 목록에서 키워드로 검색 가능`
3. 사용자가 확인하면 커밋을 생성한다:
   ```bash
   git add <변경된 파일들>
   git commit -m "<확정된 커밋 메시지>"
   ```
4. main에 병합한다:
   ```bash
   git checkout main
   git merge <브랜치명> --no-ff -m "Merge branch '<브랜치명>'"
   ```

### 5단계 — 작업 요약

병합 완료 후 다음 항목을 포함한 작업 요약을 출력한다.

- 브랜치명
- 변경된 파일 수 및 목록
- 커밋 메시지
- 병합 완료 시각
- 다음 추천 작업 (예: `npm run build`로 빌드 확인, Vercel 배포 등)
